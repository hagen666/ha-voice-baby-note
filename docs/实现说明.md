# 小爱语音喂奶记录 · 实现说明

> 一句话：**对着小爱说「喂奶了」，HA 自动识别、写进记录清单、算出距上次多久；超过 3 小时且是白天，主动播报提醒。**

![架构图](out/喂奶记录-架构图.png)

---

## 一、需要准备什么

### 硬件

| 设备 | 必需？ | 作用 |
|---|---|---|
| **HA 主机**（NAS / 树莓派 / 小主机都行） | ✅ 必需 | 大脑，跑所有自动化 |
| **带小爱的设备**（家庭屏 / 小爱音箱） | ✅ 必需 | 语音入口 + 播报出口（**只有它能提供"对话原文"**）|
| **86v1 智能面板**（可选） | ⭕ 可选 | 卧室语音入口（**拿不到对话原文，需配中枢网关走虚拟事件**）|
| **小米中枢网关** | ⭕ 视情况 | **用 86v1 面板就必需**；只用家庭屏则不需要 |
| 手机 | ⭕ 可选 | 收推送通知 |

> 我家用的是**客厅家庭屏**（小爱 + 屏幕），所以既能听、又能播报、还能看记录。

### 软件（HA 里要装的集成）

| 集成 | 来源 | 作用 |
|---|---|---|
| **Xiaomi MIoT** | HACS 第三方 | ⭐ **关键**：把家庭屏的「**对话原文**」暴露成 `sensor.xxx_conversation` |
| **Xiaomi Home**（官方小米集成） | 官方 | 提供各房间面板/家庭屏的 `notify.*_play_text`（**播报**）+ 中枢网关虚拟事件实体 |
| Mobile App | 内置 | 手机推送（可选） |

**为什么要装两个？**

| 能力 | MIoT | Xiaomi Home |
|---|---|---|
| 拿到「小爱听懂了什么」 | ✅ **能** | ❌ 拿不到 |
| 播报 TTS | ❌ 弱 | ✅ **稳定** |
| 中枢网关虚拟事件 | ❌ | ✅ **能** |

> 所以分工是：**MIoT 负责「听」，Xiaomi Home 负责「说」。**

---

## 二、核心思路（三句话）

1. **听** —— MIoT 把家庭屏听懂的每句话，变成一个传感器的值
2. **判** —— 用模板传感器把「同一句话」变成「**时间戳变化**」
   （因为传感器值不变就不会触发；时间戳变了才会触发 → 天然去重）
3. **记** —— 用 HA 的 `todo` 清单当**数据库**，一行一条，手机/面板都能看

---

## 三、数据都放在哪

| 实体 | 类型 | 作用 |
|---|---|---|
| `sensor.xxx_conversation` | MIoT 提供 | 小爱**刚听懂的原文**（例：`刚刚喂奶喂了一百一`） |
| `sensor.xiao_ai_yuan_hua` | 模板传感器（UI 创建） | 小爱原话（多设备时优先取家庭屏那条） |
| `sensor.xiao_ai_yuan_hua_shi_jian_chuo` | 模板传感器 | **时间戳**（触发信号来源） |
| `todo.bao_bao_ji_lu` | todo 清单 | ⭐ **所有育儿记录**（当前 279 条） |
| `input_datetime.wei_nai_shi_jian` | 时间助手 | 上次喂奶时间（可手动改，用于补记） |
| `sensor.shang_ci_wei_nai` | 模板传感器 | 「上次喂奶」显示用 |
| `sensor.ju_shang_ci_wei_nai_fen` | 模板传感器 | **距上次喂奶多少分钟**（实时计算） |
| `script.bu_ji_wei_nai` | 脚本 | 补记喂奶 |

### 关键：模板传感器是怎么写的

**「小爱原话」**
```jinja
{% set all = states.sensor | selectattr('entity_id','search','_conversation') | list %}
{% set pref = all | selectattr('entity_id','search','{{PREFER_PATTERN}}') | list %}
{% set e = pref if pref | count > 0 else all %}
{{ e[0].state if e | count > 0 else 'none' }}
```

**「小爱原话时间戳」**
```jinja
{% set all = states.sensor | selectattr('entity_id','search','_conversation') | list %}
{% set pref = all | selectattr('entity_id','search','{{PREFER_PATTERN}}') | list %}
{% set e = pref if pref | count > 0 else all %}
{% if e | count > 0 %}
  {{ e[0].attributes.get('timestamp') or e[0].last_changed.isoformat() }}
{% else %}none{% endif %}
```

> 这段的妙处：家里有好几个小爱（客厅/主卧/北次卧/南次卧），它**优先取客厅家庭屏**那条，取不到才用别的。

## 四、记录是怎么产生的（五条自动化）

| # | 自动化 | 触发器 | 做什么 |
|---|---|---|---|
| 1 | **小爱语音育儿记录**（核心） | 时间戳传感器变化 | 识别类型 → 提取奶量 → 写入 todo |
| 2 | 面板口令育儿记录 | 中枢网关虚拟事件 | 同样的识别逻辑，走虚拟事件通道 |
| 3 | 喂奶计时器 | 时间戳变化 / 虚拟事件 | 判断是不是「喂奶类」，是就更新上次喂奶时间 |
| 4 | 喂奶时间提醒 | 每 5 分钟 | 超过 3 小时 + 白天 → 播报 |
| 5 | 答复上次喂养时间 | 虚拟事件（问句） | 回答「上次什么时候喂的」 |

### ⭐ 先说清楚：为什么要分两条路

家里有两类「能说话」的设备，但 **HA 看到的东西完全不一样**：

| 设备 | HA 里有什么 | 能否拿到「你说了什么」 |
|---|---|---|
| **客厅家庭屏**（x8f） | `sensor.*_conversation`（对话原文）、`notify.*_play_text`（播报） | ✅ **能** |
| **86v1 面板** ×3<br>（主卧/北次卧/南次卧） | 只有 `notify.*_play_text`（播报）和 `button.*_wake_up`（唤醒） | ❌ **拿不到** |

**86v1 面板小米没开放对话内容**，HA 只知道它"在播报"，不知道它"听到了什么"。

所以：

- **家庭屏** → 走「**抓对话原文**」这条路（自由说话，话术随便）
- **86v1 面板** → 必须借「**米家 App + 中枢网关虚拟事件**」这条路（话术固定，但最稳）

---

### 链路 1：自由说话（最常用）

```
你说：「喂奶了，150毫升」
   ↓
MIoT 抓到对话原文 → sensor.xxx_conversation 变化
   ↓
模板传感器「时间戳」变化 → 触发自动化
   ↓
自动化里做 4 件事：
   ① 分类：喂奶 / 尿尿 / 便便 / 睡眠 / 辅食 / 吸奶...
   ② 提取：正则抓奶量 `(\d+(?:\.\d+)?)\s*(?:毫升|ml|cc)`
   ③ 过滤：如果是问句（「什么时候」「多久」「？」）→ 不记录
   ④ 写入 todo：`10-06 20:11 🍼 喂奶 150ml｜刚刚喂奶喂了一百一`
```

---

### 链路 1-B：86v1 面板 + 中枢网关虚拟事件（详细）

> 这条是**面板专用**的。因为面板的对话内容 HA 拿不到，只能让**米家先听懂**，再用「虚拟事件」把结果传给 HA。

#### 完整链路

```
对着 86v1 面板说固定口令「喂奶」
        ↓
【米家 App 里配的自动化】
   触发：小爱同学听到指定话术
   动作：中枢网关 → 产生虚拟事件（事件名称 =「喂奶」）
        ↓
【中枢网关】真的发出一个虚拟事件
        ↓
【HA 的 Xiaomi Home 集成】把它暴露成实体：
   event.xiaomi_cn_{{HUB_DEVICE_ID}}_hub1_virtual_event_e_4_1
        ↓
【HA 自动化】监听这个实体的 state 变化
   读 attributes['事件名称'] → 拿到「喂奶」
        ↓
分类 + 写记录（和家庭屏那条路共用同一套识别逻辑）
```

#### 米家 App 里要配什么（关键，别人复刻最容易卡在这）

**在米家 App 里，为每一个口令单独建一条自动化：**

```
米家 App → 智能 → 自动化 → 添加自动化

① 触发条件：
   选「小爱同学」→「执行指定指令」
   填入话术：喂奶

② 执行动作：
   选「中枢网关」→「产生虚拟事件」
   事件名称填：喂奶        ← 这个词就是 HA 收到的原文

③ 保存
```

**要配几条，取决于你想支持多少种口令**，例如：

| 面板说的话 | 虚拟事件名称 | HA 记成 |
|---|---|---|
| 喂奶 | `喂奶` | 🍼 喂奶 |
| 宝宝便便 | `宝宝便便` | 💩 便便 |
| 宝宝睡了 | `宝宝睡了` | 😴 睡眠 |
| 补记喂奶 20:30 | `补记喂奶 20:30` | 🍼 喂奶｜补记 |
| 询问上次喂养时间 | `主卧询问上次喂养时间` | 播报答案（不记录）|

> ⚠️ **事件名称就是 HA 收到的"原话"**，所以要写成**能被关键词识别**的完整句子。

#### 为什么有的口令要带房间名

HA 要按「你在哪个房间问的」**就近播报**，但虚拟事件里没有设备信息，
所以只能在**事件名称里带上房间名**：

```jinja
{# 从事件名称里判断房间，选择播报设备 #}
{% if '客厅' in nm %}   notify.xiaomi_cn_{{DEVICE_ID_HOME}}_x8f_play_text_a_7_3      {# 客厅家庭屏 #}
{% elif '主卧' in nm %} notify.xiaomi_cn_{{DEVICE_ID_MBR}}_86v1_play_text_a_5_3      {# 主卧面板 #}
{% elif '北次卧' in nm %}notify.xiaomi_cn_{{DEVICE_ID_NBR}}_86v1_play_text_a_5_3      {# 北次卧面板 #}
{% elif '南次卧' in nm %}notify.xiaomi_cn_{{DEVICE_ID_SBR}}_86v1_play_text_a_5_3      {# 南次卧面板 #}
{% else %}             [notify.xiaomi_cn_{{DEVICE_ID_NBR}}_86v1_play_text_a_5_3,
                        notify.xiaomi_cn_{{DEVICE_ID_SBR}}_86v1_play_text_a_5_3]      {# 兜底：两个都播 #}
{% endif %}
```

所以米家那边，**主卧面板的自动化事件名称要写成「主卧询问上次喂养时间」**，南次卧写成「南次卧…」。

#### HA 侧怎么接（重要坑）

虚拟事件在 HA 里是 **`event` 域实体**，**不能用 `platform: event` 监听**：

```yaml
# ❌ 错的：收不到
trigger:
  - platform: event
    event_type: xiaomi_cn_{{HUB_DEVICE_ID}}_hub1_virtual_event_e_4_1

# ✅ 对的：监听实体状态变化，再读属性
trigger:
  - trigger: state
    entity_id: event.xiaomi_cn_{{HUB_DEVICE_ID}}_hub1_virtual_event_e_4_1
actions:
  - variables:
      nm: "{{ trigger.to_state.attributes['事件名称'] | trim }}"
```

**完整可用的骨架：**

```yaml
- id: 'baby_log_panel'
  alias: 面板口令育儿记录（中枢虚拟事件）
  triggers:
    - trigger: state
      entity_id: event.xiaomi_cn_{{HUB_DEVICE_ID}}_hub1_virtual_event_e_4_1
  actions:
    # 1. 取事件名称当「原话」
    - variables:
        nm: "{{ trigger.to_state.attributes['事件名称'] | trim }}"
        tl: "{{ nm | lower }}"
        # 2. 正则抓奶量 / 分钟
        amt: "{{ nm | regex_findall('(\\d+(?:\\.\\d+)?)\\s*(?:毫升|ml|cc)') | first | default('', true) }}"
        mins: "{{ nm | regex_findall('(\\d+)\\s*(?:分钟|min)') | first | default('', true) }}"
    # 3. 分类
    - variables:
        kind: >-
          {% if '便便' in nm or '臭臭' in nm %}便便
          {% elif '尿布' in nm or '尿尿' in nm %}尿尿
          {% elif '辅食' in nm or '米糊' in nm %}辅食
          {% elif '睡' in nm %}睡眠
          {% elif '醒' in nm %}醒来
          {% elif '奶' in nm or '毫升' in tl or 'ml' in tl %}喂奶
          {% else %}其他{% endif %}
    # 4. 过滤问句 / 补记
    - condition: template
      value_template: "{{ kind != '其他' and not isq }}"
    # 5. 写入记录
    - action: todo.add_item
      target: { entity_id: todo.bao_bao_ji_lu }
      data:
        item: "{{ now().strftime('%m-%d %H:%M') }} 🍼 {{ kind }}{% if amt %} {{ amt }}ml{% endif %}｜{{ nm }}"
```

#### 两条路对比

| | 路径 A：家庭屏 | 路径 B：86v1 面板 |
|---|---|---|
| **话术** | 任意（「刚刚喂过奶了」「一百一」） | **固定口令**（必须在米家里配好） |
| **识别方式** | HA 用关键词猜 | 米家已经匹配好，直接给结果 |
| **准确率** | 取决于关键词覆盖 | **更稳**（命中就是命中） |
| **要配置的地方** | HA 里配自动化 | **米家 + HA 两边都要配** |
| **改话术的成本** | 改 HA 就行 | 要改米家 + HA |
| **适合场景** | 客厅，随口说 | 卧室/床边，说固定口令 |

> 实际用下来：**客厅随口说**用 A（方便），**卧室半夜迷糊**用 B（稳、不用想措辞）。

## 五、踩过的坑（关键）

### ❶ `event` 域的实体，不能用 `platform: event` 监听

中枢网关的虚拟事件是 `event.xxx_virtual_event` 这种实体。很多人会写：

```yaml
# ❌ 错误：这样收不到
trigger:
  - platform: event
    event_type: xiaomi_cn_xxx_virtual_event_e_4_1
```

**正确做法**是监听**实体的状态变化**，再读属性：

```yaml
# ✅ 正确
trigger:
  - trigger: state
    entity_id: event.xiaomi_cn_xxx_virtual_event_e_4_1
condition:
  - condition: template
    value_template: "{{ trigger.to_state.attributes['事件名称'] == '喂奶' }}"
```

> 原因：虚拟事件在 HA 里被建模成「event 实体」，事件名在 `事件名称` 属性里。

### ❷ 直接监听对话传感器会重复触发

`sensor.xxx_conversation` 的值如果**没变**，是不会触发 `state` 的。
但只要变了一次（哪怕是自己刷新），就可能重复记录。

**解法**：多套一层「时间戳传感器」，用 `last_changed` 或设备自带 `timestamp` 属性，
再配合 automation 的 `last_triggered` 比较：

```jinja
{{ s not in ['none','unknown','unavailable','']
   and (last is none or as_datetime(s) > last) }}
```

### ❸ 用 `todo` 当数据库特别好用

- 有现成 UI（HA 首页就能加/删/勾）
- 有 API（`todo.get_items` / `todo.add_item`）
- 手机 App 直接能看
- **不用装数据库、不用写 SQL**

> 279 条记录跑了一个多月，完全够用。

### ❹ 一定要过滤「问句」

「上次什么时候喂的」里也有「喂」字，不加过滤就会被记成一次喂奶。

**过滤词**：什么时候 / 多久 / 几点 / 上次 / 查询 / ？…
```jinja
{% set isq = ('什么时候' in t) or ('多久' in t) or ('上次' in t) or ('？' in t) ... %}
{{ key and fresh and not isq }}
```

### ❺ 强关键词 vs 弱关键词

「奶」这个字太宽泛（可能出现在「奶瓶洗了」），所以设了两级：

- **强关键词**（单独出现就记）：奶 / 毫升 / ml / 尿布 / 便便 / 辅食…
- **弱关键词**（要配合「宝宝/娃/闺女」才记）：睡 / 醒…

### ❻ 中文数字识别

小爱经常说「喂了一百一」，不是「110」。
现在靠**原文兜底**保存（记录里能看到原话），奶量提取只认阿拉伯数字 —— **够用，但不完美**。

## 六、记录长什么样

在 HA 的「宝宝记录」清单里，一条一行：

```

```

格式：`月-日 时:分  [emoji] 类型 [奶量] ｜小爱原话`

| emoji | 含义 |
|---|---|
| 🍼 | 喂奶 |
| 🧷 | 换尿布 / 尿尿 |
| 💩 | 便便 |
| 😴 | 睡眠 |
| ☀️ | 醒来 |
| 💧 | 喝水 |
| 🥣 | 辅食 |
| 🥛 | 吸奶 |

## 七、别人想复刻，按这个顺序做

### 第 1 步：装集成
1. 装 **Xiaomi MIoT**（HACS）→ 加家庭屏设备
2. 装 **Xiaomi Home**（官方）→ 同一个小米账号
3. 确认能看到 `sensor.xxx_conversation`（MIoT 提供）

### 第 2 步：建 4 个助手
设置 → 设备与服务 → 辅助元素 → 创建：

| 类型 | 名称 |
|---|---|
| 模板传感器 | 小爱原话 |
| 模板传感器 | 小爱原话时间戳 |
| 模板传感器 | 上次喂奶 |
| 模板传感器 | 距上次喂奶（分钟） |
| 日期时间 | 上次喂奶时间（可补记） |
| 待办清单 | 宝宝记录 |

### 第 3 步：建自动化（路径 A）

- **小爱语音育儿记录**：触发 = 时间戳变化 → 分类 + 写 todo
- **喂奶计时器**：触发 = 时间戳变化 → 更新上次喂奶时间

### 第 4 步：配米家 App（只用面板才需要，路径 B）

**这一步在米家 App 里做，不在 HA 里**，是最容易漏的：

```
米家 App → 智能 → 自动化 → 添加
  ① 触发条件：小爱同学 → 执行指定指令 → 填话术「喂奶」
  ② 执行动作：中枢网关 → 产生虚拟事件 → 事件名称填「喂奶」
  ③ 保存
```

**每个口令建一条**（喂奶 / 宝宝便便 / 宝宝睡了 / 补记喂奶 20:30 …）。
**卧室面板记得在事件名称里带房间名**：`主卧询问上次喂养时间`。

### 第 5 步：建自动化（路径 B）

- **面板口令育儿记录**：触发 = `event.*_virtual_event` **状态变化** → 读 `事件名称` → 分类 + 写 todo
- **答复上次喂养时间**：按事件名称里的房间名，选择就近播报

> ⚠️ 注意：**不能用 `platform: event`**，要用 `trigger: state` 监听 event 实体。

### 第 6 步：建提醒

- **喂奶时间提醒**：每 5 分钟检查，>3 小时且白天 → `notify.send_message` 播报

### 第 7 步：建脚本

- **补记喂奶**：检查是否当天 → 写 todo

### 第 8 步：做面板

- 一个「宝宝记录」仪表盘：显示距上次多久 + 补记按钮 + todo 清单

## 八、这套设计好在哪

| 优点 | 说明 |
|---|---|
| **零操作** | 说一句话就行，不用点任何按钮 |
| **有兜底** | 语音识别不准也不怕，原话会存下来，还能手动补记 |
| **不打扰** | 夜里不提醒；问句不误记 |
| **可查询** | 随时问「上次什么时候喂的」 |
| **数据在自己手里** | 全在 HA 本地，不上传任何云 |
| **零成本** | 不用订阅、不用买服务 |

## 九、局限（实话）

| 局限 | 说明 |
|---|---|
| 中文数字识别不全 | 「一百一」不会自动变成 110ml，只保留原话 |
| 依赖小爱识别准确率 | 口齿不清/环境吵可能识别错 |
| 需要家庭屏或音箱常在线 | 设备离线就听不到 |
| MIoT 是社区集成 | 小米固件升级偶尔会破坏，需要跟进更新 |
